Constraints beyond the arrows

Applications are unique by student/job, including withdrawn records. Their composite student/CV key prevents using another student's review. Current CV pointers reference that student's immutable version. CV evidence skill keys include version/kind/evidence ordinal. Skill aliases are scoped by skill; the service rejects ambiguous normalized phrases. The current scoring policy is a singleton pointer; original application policy/score/explanation remain saved separately. CV approval belongs to the exact confirmed version; new versions and legacy missing decisions are Pending. Account disablement preserves these records. Permanent erasure removes scoped dependent records and notices.

Vacancy capacity derives from committed hired applications. Interview events are ordered by application and revision. Scorecards reference the confirmed occurrence. Audit targets are scalar identifiers so the activity can survive target erasure.

job_catalog_lock is an independent singleton mutex. Original application policy is an immutable version label, not a database foreign key. Reviewed skills, evidence and certifications belong to CV versions; there is no persisted match cache or redundant mutable student-skill table.
