# Reproducing and verifying the demo

## Project and tools

The root pom.xml builds Java 21 Swing/JDBC code; the main class is `smarthire.Main`. Open the root as a Maven project in NetBeans. No GUI Builder forms, web server or Python runtime are required for the app. On this laptop use PowerShell 7 and dot-source `scripts/dev-env.ps1` for the portable JDK, Maven and dependency cache. `scripts/start-netbeans.ps1` selects the same local JDK/cache.

Runtime checks on 2026-11-05 returned Temurin **21.0.13+9**, Maven **3.10.0**, and MySQL client/server **8.4.13** (server queried during clean smoke). Workbench `--version` returned **26.10.0**. NetBeans **31** is the installed distribution recorded during environment setup; a fresh version command did not return text, so it is not a new visual IDE verification.

The checked installation lives under `.tools`; follow environment-setup.md for installation/archive checks and scripts. The scripts target this laptop's layout. On another machine install Java 21, MySQL, Maven and optionally NetBeans, create UTF-8 `smarthire` and `smarthire_test` databases, and grant a local application user privileges on those databases. Database.load uses loopback port 3306 and these two schema names.

Create a private `.local/application.properties` with `user=` and `password=` entries for that local account, or use the laptop launcher with `.local/database.json` generated by configure-mysql.ps1. Do not copy credentials into source or documentation. Startup executes `src/main/resources/db/schema.sql` to create missing tables and initial policy pointers; it does not drop tables or reset data. Use explicit seeding to add the fictional accounts/jobs. DemoSeed is the executable account seed, DemoJobs the additive catalog/job seed; raw SQL with plaintext passwords is deliberately unnecessary.

## Build and run

```powershell
. .\scripts\dev-env.ps1
.\scripts\start-mysql.ps1
.\scripts\run.ps1 -SeedDemo
.\scripts\run.ps1
```

The first Maven build on another machine may download pinned dependencies/plugins and needs connectivity. Once the cache is populated, build/tests/classpath generation work with `mvn -o`. Runtime uses only local MySQL and managed files. The JAR is not shaded: use the launcher, or build the classpath then launch explicitly:

```powershell
mvn -o package dependency:build-classpath '-Dmdep.outputFile=target/runtime-classpath.txt' '-DincludeScope=runtime'
$smartHireClasspath = (Get-Content target/runtime-classpath.txt -Raw).Trim()
java -cp "target/classes;$smartHireClasspath" smarthire.Main
```

In NetBeans set the main class to `smarthire.Main` and working directory to the project root. Generate private configuration with the launcher first. Stop an existing app before opening another instance: managed storage takes an exclusive process lock. Close and relaunch after rebuilding UI changes.

## MySQL Workbench

Start the server with `scripts/start-mysql.ps1`; Workbench is a client and does not start it. Launch `scripts/start-workbench.ps1`, click the plus beside MySQL Connections, name it SmartHire local, choose Standard TCP/IP, host `127.0.0.1`, port `3306`, username `smarthire`, and default schema `smarthire`. Use the generated local password from `.local/database.json` when prompted, then Test Connection and open it. Refresh Schemas after the first app launch. Use the SQL editor to inspect `SELECT VERSION();` and `SHOW TABLES;`.

For schema import, open `src/main/resources/db/schema.sql` in an SQL tab attached to the intended database and execute it. The target database and grants must already exist. Choose `smarthire_test` for test inspection, never for the live presentation. The complete ER export is `docs/database/er-diagram.html`; its inline SVG and exact foreign-key table work offline. Standalone SVG and editable Mermaid source are beside it. It shows all 23 tables and 25 foreign keys, including composite CV ownership, per-version admin approval/reviewer, circular history, notification read state and current-policy pointers.

## Automated checks

```powershell
. .\scripts\dev-env.ps1
mvn -o test
.\scripts\verify.ps1 -Offline
.\scripts\verify.ps1 -Offline -CleanDatabaseSmoke
```

Unit-only tests require no server; database classes are skipped unless explicitly enabled. The ordinary full integration command uses `smarthire_test`, creates uniquely named fictional data and removes only that data. It does not reset shared tables. Workflow tests restore their starting scoring policy. Do not run these suites concurrently against a shared test database.

Clean smoke is a separate opt-in because it needs local administrative CREATE/DROP DATABASE privileges. It reads `.local/mysql-admin.ini` without printing credentials, creates an unpredictable `smarthire_smoke_<32 hex>` schema, runs schema initialization twice, additive seeds and a real parser/review/matching/application/notification/restart journey, then drops only that schema in finally. Existing `smarthire`/`smarthire_test` are untouched. The root account is used only by this isolated check, never by the desktop app. To use another private config:

```powershell
mvn -o '-Dsmarthire.cleanSmoke=true' '-Dsmarthire.smokeAdminConfig=C:/private/mysql-admin.ini' '-Dtest=CleanDatabaseSmokeTest' test
```

The alternate file needs Java-properties-compatible `user`/`password` entries; the generated local INI is compatible. If a process is forcibly killed before cleanup, inspect for the generated smoke schema and remove only that exact disposable schema. No reset command is provided for the live database. For a fresh presentation, register new fictional students and create new postings, or use a separately backed-up clean installation. Additive seed never erases history.

## Moving or backing up

Close the app and stop writes. Export `smarthire` using Workbench Data Export (structure and data), and copy `.local/documents` from the same point in time. Preserve UUID names, original bytes and all historical versions. Restore SQL to the new `smarthire` schema and copy the managed store to the new project's `.local/documents` before launching. Configure new local credentials and tooling paths; do not publish the old `.local` directory or database dump. For a filesystem copy of the MySQL data directory, stop MySQL first and use a compatible server version; a logical export is preferred.

Copying the database alone loses original CV/circular bytes. Copying files alone loses ownership, reviewed versions, applications, alerts and policy history. Startup reconciliation preserves referenced history, reports missing/changed files and removes only abandoned generated files. Never use cleanup to remove a referenced document.

## Supplied artifacts and regeneration

Use demo-guide.md for the three-role script, sample results and manual acceptance checklist. The CV PDFs are delivered under `output/pdf` and mirrored in `src/test/resources/demo` for actual parser tests. Existing DOCX/PDF fixtures in `src/test/resources/documents` cover text, tables, encryption and textless input. The circular supplied earlier remains under `output/pdf`.

`python scripts/export-er.py` regenerates SVG/HTML/Mermaid using Python's standard library. Optional `python scripts/generate-demo-cvs.py` needs ReportLab and regenerates the same fictional CV PDFs and test copies. These authoring tools are not runtime dependencies. Keep generated fixtures with source so ordinary app/test users need no Python installation.

See implementation-status.md for measured results and disclosed limitations. Automated service/database checks do not replace live Swing, keyboard, file-dialog or display-scaling acceptance.
